# Paneltec Safety Portal — project brief for Claude

Read this first in every session. It is the whole-system picture, the owner's
decisions, and the build order. The owner (Stephen, Paneltec Pty Ltd,
Launceston TAS) is non-technical: explain in plain words, one step at a time,
and never ask him to run commands.

## What this repository is

ONE system with three parts. All three are in scope. Nothing here is "just the
phone app".

| Part | Where | What it is | Status |
|---|---|---|---|
| Backend | `backend/` | FastAPI + MongoDB. Simpro sync, workers, sites, jobs, sign-on, forms, SWMS, hazards/incidents/pre-starts, AI helpers, email, backups. ~62k lines. | Works. Hosted on Emergent today (`https://whs-compliance.preview.emergentagent.com`). |
| Web portal | `frontend/` | React office portal: Daily Pre-Starts, Site Diary, Hazard/Incident/Inspection Reports, Site Visitors, Risk Assessments, Forms, Suppliers, Document Library, Fleet, Sites, Workers, Users & Permissions, Program Schematic, etc. ~92k lines. | Works; the office uses it daily. Keep it, maintain it, extend it. |
| Phone app | `mobile/` | Expo / React Native field app "Paneltec Group Field". | Rebuilt Sept 2026 to the owner's design (see below). APK did not open on phones before the fixes below; verify on the next build. |

The app was originally generated by Emergent. Emergent is no longer the
developer: Claude is. Emergent still HOSTS the backend + portal until the
hosting move (last step).

## Owner's decisions (do not re-ask)

- Finish THIS codebase end-to-end. No rewrite.
- Phone login = onboarding QR card printed from the portal → worker scans it →
  downloads the app → app reads their profile → they choose a 4-digit PIN.
  (Backend: `backend/mobile_auth.py`, `mobile_onboarding_cards.py`;
  web landing: `frontend/src/pages/OnboardMobileLanding.jsx`;
  app: `mobile/app/onboard.tsx`, `mobile/app/(auth)/welcome.tsx`.)
- Phone look and feel ("Option B"): navy screens `#1B3D66`, off-white
  bordered cards `#F4F6F9` / border `#B9C6D6`, orange icons + primary actions
  `#F97316`, bright green go-actions and positive states `#22C55E`, grey
  secondary text. Tokens in `mobile/src/theme/colors.ts`; shared pieces in
  `mobile/src/components/ui.tsx`. Tabs: Home · QR Scan · My Work · Profile.
  No "Coming soon" tiles anywhere — every tile opens a real screen.
- Job flow: Simpro → the owner's self-hosted whiteboard → manager issues the
  job → phone gets a PUSH notification (SMS optional backup) → one job screen
  (map/address, when, task, Accept/Decline; then Navigate + Sign on) → sign-on
  tied to the job → straight into the daily pre-start.
  Backend already has `mobile_daily_jobs.py` (today / accept / decline),
  `mobile/push/register`, site sign-on with `job_id`.
- Hosting will move from Emergent to the owner's UGREEN NAS (Docker/Portainer)
  LAST, as one simple docker-compose paste. Don't start it before the phone
  app is proven on a device.
- Never commit `.apk` files (they exceed GitHub's limit). APKs are built by
  `.github/workflows/android-apk.yml` and published to the GitHub Release
  tagged `latest`.
