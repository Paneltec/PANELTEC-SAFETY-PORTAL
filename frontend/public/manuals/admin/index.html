WHS obligations don't stop at the platform boundary. Paneltec Civil captures evidence of compliance — SWMS acknowledgements, pre-starts, incident reports, cert records — but the underlying legal duty to induct workers, verify certifications, and provide safe work environments rests with the PCBU. See Safe Work Australia for the current Model WHS Regulations.

1. Intelligence Centre (dashboard)

The Intelligence Centre at /app/dashboard is your live compliance snapshot. It shows monitoring scope, records needing attention, workspace scope, and a compliance attention score.

  • Create & Capture — six action tiles for the most common flows (AI SWMS, Pre-Starts, Site Diary AI, Hazard reports from photos, Incident reports, Inspection reports).
  • Compliance Snapshot — metrics for the current quarter with the compliance attention score.
  • Ask Intelligence — natural-language querying of preserved compliance evidence.
  • Quick actions — four highlight tiles for org-wide oversight.

2. Forms — templates & assignments

Manage form templates at /app/forms. Every template belongs to a category (SWMS, pre-start, hazard, incident, inspection, risk assessment, site diary, general).

Creating & editing

  1. Click New Template (or Build with AI for an AI-assisted draft).
  2. Set name, category, description.
  3. Add fields. Each field has label, type (text, number, date, select, radio, checkbox, photo, signature, GPS, worker picker, site picker, asset scan), help text, per-field style overrides.
  4. Group related fields under section headers by inserting a section_header field type. Collapsible section groups appear on both web and mobile.
  5. Save. Templates are versioned in-place.

Assignments matrix

Open Form Assignments under Settings to tag each template with a kinds/asset-types/roles/companies matrix. Workers only see the forms tagged for their role or asset assignment. Auto-seed heuristic handles obvious matches (e.g. "Trailer Pre-start" → trailer asset-type); admin override wins.

3. Certification gate (default OFF)

As of v.132kp the certification gate is disabled by default. Every worker can open every form regardless of cert status.

Truth table

Global env FORM_CERT_GATE_ENABLEDPer-template toggleEnforcement
unset / off (default)anythingOPEN
onoffOPEN
onon + empty required certsOPEN
onon + required certs configuredGATED

Re-enabling the gate

  1. Add FORM_CERT_GATE_ENABLED=1 to /app/backend/.env.
  2. Restart backend (sudo supervisorctl restart backend).
  3. In each template editor, tick "Require certifications to open this form" under Access control.
  4. Select the required cert slugs in the qualification picker.
⚠
A White Card (Construction Induction) is required by AU law for construction work. Every worker was auto-seeded with a placeholder White Card record on ship v.132kp; admins should verify and fill real issue / expiry dates in the certifications matrix. Placeholders carry status: "seeded".

4. SWMS — authoring & visibility

Author SWMS at /app/swms. Assign visibility per SWMS via the applies_to matrix (roles, worker IDs, company IDs, asset types).

Workers only see SWMS that match their assignment matrix or are legacy-null (see v.132kn in the changelog for the visibility contract). Admin audit widget for un-tagged SWMS is a queued follow-up.

5. Documents & shared reference folders

At /app/document-library. Two visibility modes for folders:

  • Private (default) — worker sees only files they uploaded or that are assigned to them.
  • Shared reference — visible to every worker in the org. Auto-seeded on well-known names (SDS, Chemical Register, Australian Standards, Toolbox Talks, Company Policies, Procedures). Toggle manually via the Globe icon in the folder card hover strip (grid view) or via the SHARED pill in the tree view.

Confirmation dialog fires when disarming a shared folder with ≥50 files to prevent accidental worker lockout.

6. Compliance / Audit exports

At /app/compliance/audit-exports. Every export is a signed PDF or CSV with the timestamp, initiator, and record IDs baked in. Post-v.132ke the list uses a responsive flex-card layout instead of a horizontal-scrolling table — safe on any viewport.

7. Site QR & visitor sign-in

Each site record carries a rotating scan_token. The site QR PDF (available from the site detail page) encodes the public URL /scan/site/<token>. Anyone scanning the QR from a phone browser lands on:

  • The kiosk / worker sign-on screen if they're already signed in.
  • The public visitor sign-in form if they have no session.

Fixed in v.132kl: stale JWTs on public routes no longer bounce visitors to the sign-in page — the axios interceptor now clears the poisoned token and reloads once (single-flight guard) so the visitor form renders cleanly.

8. PDF upload & layered matcher

Upload PDFs of scanned or exported forms via the Upload PDF flow in the admin captures area. The v.132kh matcher runs five layered stages:

  1. Filename regex — anchored patterns for common shapes (^incident[-_ ], [-_ ]ssra[-_ ], etc.).
  2. Title-token overlap — first content line matched against template names.
  3. PDF metadata — /Title, /Subject, /Author scan.
  4. Text-scan keyword scoring — per-category anchor keyword count (threshold ≥ 3 distinct hits).
  5. LLM fallback — Claude Sonnet 4.5 classifies unknown PDFs when stages 1–4 miss. Cached per SHA.

Every upload emits a [pdf-match] log line with file, sha, stage, matched template ID, and top-3 candidate scores — grep /var/log/supervisor/backend.err.log for diagnostics.

9. Service Check Sheet layout

The Service Check Sheet template renders as a horizontal inline row — [Label] [✗] [✓] [NA] [Notes] — grouped into collapsible sections (Tires, Steering, Brakes, etc.) with live ATTENTION / COMPLETE pills per section. Sections with only regular fields fold cleanly under the section header (fix in v.132kd1).

10. Live preview mode

The admin console at /app/settings/preview previews the mobile app as any role or specific worker. Preview JWTs carry preview: true and default to role: worker when "role-only" is selected.

Caveats: preview mode uses a synthetic user id. Per-user overrides (site pinning, personal cert dates) don't apply. Real workers see their own scoped data on their own phone.

11. Users & roles

Manage at /app/settings/users. Roles: admin, hseq_lead, supervisor, manager, hseq_manager (+ read-only / creator variants), responsible_manager, report_emailing_admin, general_user, worker, contractor_rep, paneltec_civil, viatec_traffic, auditor.

See the permissions matrix at /app/settings/permissions for the granular view/edit/email/delete grants per role.

12. Integrations

Configured at /app/settings/integrations: Simpro (staff sync + jobs), Microsoft 365 (email), TextMagic (SMS), Navixy (vehicle tracking). Each integration surfaces a Not connected / Connected pill on the card.

13. Common issues

Worker sees empty SDS folder on mobile

Fixed in v.132km. If the folder is still empty for a specific worker, confirm the folder is flagged Shared reference (SHARED pill visible in the tree view). If not, click the Globe toggle to flip it ON.

Worker sees empty SWMS list on mobile

Fixed in v.132kn. If it recurs, curl the endpoint with the worker's JWT: curl -H "Authorization: Bearer <jwt>" $URL/api/swms. Empty response = applies_to matrix excludes the worker; admin needs to add their role or worker ID to the SWMS.

QR scan bounces to login instead of visitor form

Fixed in v.132kl. Confirm the worker's phone has the latest build; force cache clear if not.

PDF upload returns "Unmatched template"

Check the [pdf-match] log line. If stage=none matched=None, the PDF genuinely has no matching template signature. If top3 shows a candidate with score 1 or 2, tune _CATEGORY_KEYWORDS in backend/imports.py.
